# ARM resource JSON — representação de `Microsoft.Compute/virtualMachines`

## 1. Identificação

- **Nome oficial da superfície de export**: representação de recurso do **Azure Resource Manager (ARM)** para máquinas virtuais — o corpo de resposta de `200 OK` da operação **"Virtual Machines - Get"** da API REST do Azure Compute. É o "model view" canónico de uma instância.
- **Documento oficial principal (corpo da resposta `GET`)**: "Virtual Machines - Get" (REST API, Azure Compute) —
  <https://learn.microsoft.com/en-us/rest/api/compute/virtual-machines/get?view=rest-compute-2026-04-01&tabs=HTTP> — consultado em **2026-10-14**.
- **Documentos de apoio consultados em 2026-10-14**:
  - "Virtual Machines - List All" (REST API, Azure Compute) — <https://learn.microsoft.com/en-us/rest/api/compute/virtual-machines/list-all?view=rest-compute-2026-04-01&tabs=HTTP> — a única resposta oficial com **todas** as propriedades de nível `properties.*` simultaneamente presentes e com valor.
  - "Microsoft.Compute/virtualMachines 2026-04-01 — Bicep, ARM template & Terraform AzAPI reference" — <https://learn.microsoft.com/en-us/azure/templates/microsoft.compute/2026-04-01/virtualmachines> — estrutura completa, aninhamento e tipos de cada propriedade.
  - "Microsoft.Compute/virtualMachines — Bicep, ARM template & Terraform AzAPI reference" (latest) — <https://learn.microsoft.com/en-us/azure/templates/microsoft.compute/virtualmachines>
- **Versão/schema de referência**: **`api-version=2026-04-01`** do Azure Compute (a versão `2024-11-01` redireciona para esta). O `id` e o `type` do recurso são `Microsoft.Compute/virtualMachines`.

### 1.1 Nota de método (ler primeiro)

A página oficial do `GET` **não inclui**, na versão recuperável desta investigação, a tabela de *Definitions* com uma linha por campo aninhado (o `web_fetch` da página devolve sempre os URI Parameters, a tabela de Responses, o Security e os **Examples**, truncando antes das definições de tipo). Consequentemente:

- A **estrutura, os nomes exatos e o aninhamento** são comprovados por **dois** documentos oficiais independentes: (a) as respostas de exemplo oficiais do `GET` e do `List All`; (b) a secção "Bicep resource definition" / "Property Values" da referência de templates ARM, que enumera cada propriedade com o seu tipo.
- Onde o tipo documentado é explícito na referência de templates, ele é transcrito com o valor oficial (`bool`, `int`, `string`, `string[]`, `'Enum'`).
- **Não** se afirma aqui nenhuma propriedade que não tenha sido lida. Ver §4.

## 2. Mecanismo e entrega

- **Mecanismo**: API REST do Azure Resource Manager (plano de controlo). Não é um mecanismo de exportação push.
- **Endpoint documentado**:

```
GET https://management.azure.com/subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}/providers/Microsoft.Compute/virtualMachines/{vmName}?api-version=2026-04-01
```

com o parâmetro opcional `$expand` (`InstanceView` ou `UserData`) — <https://learn.microsoft.com/en-us/rest/api/compute/virtual-machines/get?view=rest-compute-2026-04-01&tabs=HTTP>

- **Parâmetros de URI (todos documentados, obrigatoriedade explícita)** — <https://learn.microsoft.com/en-us/rest/api/compute/virtual-machines/get?view=rest-compute-2026-04-01&tabs=HTTP>:

| Nome | In | Required | Type | Descrição |
|---|---|---|---|---|
| resourceGroupName | path | true | string (minLength 1, maxLength 90) | The name of the resource group. The name is case insensitive. |
| subscriptionId | path | true | string (minLength 1) | The ID of the target subscription. |
| vmName | path | true | string | The name of the virtual machine. |
| api-version | query | true | string (minLength 1) | The API version to use for this operation. |
| $expand | query | false | `InstanceViewTypes` | 'InstanceView' retrieves a snapshot of the runtime properties of the virtual machine that is managed by the platform and can change outside of control plane operations. 'UserData' retrieves the UserData property as part of the VM model view that was provided by the user during the VM Create/Update operation. |

- **Respostas documentadas**: `200 OK` → tipo **`VirtualMachine`** ("Azure operation completed successfully."); outros códigos → `CloudError`.
- **Opção de enumeração em massa**: `List All`, que devolve `VirtualMachineListResult` com `value: VirtualMachine[]` e `nextLink` — <https://learn.microsoft.com/en-us/rest/api/compute/virtual-machines/list-all?view=rest-compute-2026-04-01&tabs=HTTP>
- **Segurança**: `oauth2`, flow `implicit`, authorization URL `https://login.microsoftonline.com/common/oauth2/authorize`, scope `user_impersonation`.
- **Formato / compressão / particionamento**: não aplicável (resposta HTTP JSON). **Não existe** caminho de blob, particionamento, manifesto ou compressão documentados para esta superfície.

## 5. Divergências conhecidas

1. **`properties.provisioningState` não é apenas de leitura na prática documental.** Aparece em **todas** as respostas oficiais de exemplo do `GET`/`List All` com o valor `Succeeded`, mas também é aceite em pedidos de criação/atualização. A documentação consultada não afirma se é de leitura. Registado — não decidir por conta própria.
2. **`properties.userData` só aparece com `$expand`.** No `GET` sem `$expand`, a documentação afirma que 'UserData' é devolvido apenas com `$expand=UserData`. Um simulador que emita `userData` por omissão estará a divergir do comportamento documentado.
3. **`resources[]` (extensões) só aparece em alguns exemplos.** Presente no exemplo do `GET` com `$expand=userData` e nas respostas do `List All`, ausente nos restantes exemplos do `GET`. A documentação não afirma se está sempre presente.
4. **`plan` e `zones` aparecem em exemplos diferentes.** `plan` está documentado como propriedade de nível superior mas **não** aparece em nenhum exemplo do `GET`; `zones` aparece no `List All` e não nos exemplos do `GET`. Ambas são listadas porque a referência de templates as documenta explicitamente para o tipo.
5. **Valores de exemplo não são valores permitidos.** Muitos exemplos oficiais usam `"aaaa…"`, `"{vmId}"`, `"{virtualMachineName}"` como *placeholders*. **Não** devem ser tratados como valores válidos nem como formato de dados.
6. **`properties.storageProfile.imageReference.version` = `latest` vs. `exactVersion`.** O `List All` mostra ambos no mesmo exemplo (`"version": "4.127.20170406"` e `"exactVersion": "aaaaaaaaaaaaa"`), evidenciando que a versão resolvida pode ser exposta separadamente — mas `exactVersion` não faz parte da lista de propriedades de deployment da referência de templates.
7. **`api-version` pedida vs. devolvida.** O `GET` com `?view=rest-compute-2024-11-01` foi **redirecionado** pela própria documentação para `2026-04-01` (`viewFallbackFrom=rest-compute-2024-11-01`). Registado: a versão estável publicada é a `2026-04-01`.
8. **Ficheiro de definições não lido.** Conforme §4, a tabela de *Definitions* do `GET` não foi recuperável; portanto esta spec é **estruturalmente** fiel mas **não** afirma obrigatoriedade campo a campo a partir da fonte REST. Qualquer campo cuja obrigatoriedade não esteja marcada como `true` nesta spec deve ser tratado como desconhecido, e não como opcional.
